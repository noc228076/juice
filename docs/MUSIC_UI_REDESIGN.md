# 音乐模块 UI 重构方案

> 目标：把「我的音乐台」从「功能堆出来的控制面板」改成「一个有自己面孔的播放器」，
> 同时保持与本站其余 12 个模块同一套视觉语言。

---

## 一、诊断：现在的问题

用 taste-skill 的 app-screen 清单逐条对照，现有音乐模块命中了这些「生成感」特征：

| 问题 | 现状 | 依据 |
| --- | --- | --- |
| 播放器是「工具条」不是「播放器」 | 96px 高，封面 64px 圆角方块，控件挤在一行小按钮里 | 播放条应 64/72/90 三档之一，封面 = 条高 − 18px |
| 列表信息密度失控 | 行高约 44px，但塞了 5 个元素（图标/收藏/加歌单/标题+歌手/时长/箭头） | 两行带媒体的行应 56–92px（中位 72），媒体 48–50px |
| 每行两个功能按钮抢注意力 | `♡` 和 `＋` 常驻显示，136 行就是 272 个按钮 | 行内操作应在 hover 时出现 |
| 强调色铺得太广 | 青色出现在图标、按钮、边框、标签、进度条、行高亮 | 强调色面积应 ≤5%，只用于「正在播放 / 进度填充 / 主按钮」 |
| 数字不对齐 | 时长 `04:19` 是比例数字，且右边缘与行尾箭头不齐 | 数字右对齐 + `tabular-nums`，一行一个右边缘 |
| 圆角混用 | 同一屏出现 6/8/14/20/28px 五种圆角 | 三级：小元素 8 / 卡片 20 / 大容器 28，胶囊 999 |
| 玻璃用在滚动区 | `.mu-row` hover 带 `backdrop-filter: blur(2px)` | 滚动内容不要用 backdrop-filter（性能崩溃），只给固定层 |
| 没有「产品面孔」 | 顶栏只有「我的音乐台」标题 + 副标题，无标识 | 需要 mark + 名称 + 一个只有这个产品有的元素 |

## 二、参考结论（调研 7 个开源项目后）

**第一参考 Feishin**（`glassy-dark` 主题）：播放条 `rgba(0,0,0,.4)` + `blur(2rem)`、
卡片 18px、封面 8px、弹层 `rgba(4,4,9,.5)` + `blur(2rem)`；三段式 grid；侧栏 260/80px 折叠。
→ 玻璃参数直接可用。

**第二参考 YesPlayMusic**（中文 Web 音乐原生案例）：播放条 64px + 封面 46px + 顶部 2px 进度条
+ 三列等分；歌词页封面 54vh、左右双栏、首尾各留 50vh、`scrollIntoView({block:'center'})`。
→ 中文歌词排版与沉浸页结构直接可用。

**第三参考 Spotify**：面板化布局（黑色缝隙 + 独立圆角面板）、token 体系
（行高 64/80/104、圆角 2/4/6/8/16/9999、动效 50/100/150/200/250/300ms + `cubic-bezier(.3,0,0,1)`）、
`repeat(auto-fill, minmax(--min-column-width, 1fr))` 卡片网格。

**专项**：AMLL 的歌词弹簧（`damping = sqrt(stiffness) × 2.2`、500ms 自动回正）；
youtube-music 的 `clamp(1.4rem, 1.1vmax, 3rem)` 流体字号。

### 与 taste-skill 的冲突及裁定

taste-skill 明令禁止「glows, glass, backdrop blur」。但它的研究对象是**工作型 app screen**
（dashboard / admin / 财务 / 设置），而音乐播放器是**媒体消费界面**——行业标杆
（Apple Music、Spotify、Feishin、YesPlayMusic）全都用玻璃与模糊，因为播放器需要「内容在
界面之下透出来」的纵深感。

**裁定**：采纳结构与排版纪律（行高、字号阶梯、数字对齐、单一强调色、无斑马纹、无 KPI 图标、
行内操作 hover 出现、右边缘统一），**保留**本站既定的玻璃语汇，但严格限制在**固定层**
（播放条 / 沉浸页 / 弹层），滚动内容一律用不透明表面。这也正好符合 taste-skill 的性能建议。

## 三、设计 token（新增，挂在 `#mod-music` 下）

```css
#mod-music {
  /* —— 间距：4px 基准 —— */
  --mu-gap-1: 4px;  --mu-gap-2: 8px;  --mu-gap-3: 12px;
  --mu-gap-4: 16px; --mu-gap-5: 20px; --mu-gap-6: 24px;

  /* —— 圆角：三级 + 胶囊 —— */
  --mu-r-sm: 8px;    /* 封面缩略图、标签、输入框 */
  --mu-r-md: 20px;   /* 卡片、面板 */
  --mu-r-lg: 28px;   /* 沉浸页容器、大弹层 */
  --mu-r-pill: 999px;

  /* —— 表面：滚动区不透明，固定层玻璃 —— */
  --mu-surface: var(--card-solid);          /* 卡片实底 */
  --mu-surface-2: rgba(255,255,255,.03);    /* 卡片内二级块 */
  --mu-glass: rgba(11,12,16,.72);           /* 播放条 / 顶栏 */
  --mu-glass-strong: rgba(8,10,14,.92);     /* 沉浸页 */

  /* —— 文字三级（对比度 ≥4.5:1） —— */
  --mu-tx: var(--tx);
  --mu-tx-2: var(--tx-dim);
  --mu-tx-3: var(--tx-faint);

  /* —— 行高 —— */
  --mu-row: 64px;         /* 两行带媒体，标准 */
  --mu-row-media: 48px;   /* 行内封面 */

  /* —— 动效 —— */
  --mu-ease: cubic-bezier(.3,0,0,1);
  --mu-t-fast: 150ms;
  --mu-t-base: 250ms;
  --mu-t-slow: 450ms;
}
```

字号阶梯（全站统一，只用这 6 档）：
`11 / 12.5 / 14 / 16 / 20 / 26`

## 四、布局骨架

```
┌─────────────────────────────────────────────┐
│  header（32px）：mark + 我的音乐台 + 音源状态  │   ← 有产品面孔
├─────────────────────────────────────────────┤
│  tabs（胶囊，fit-content）：搜索 / 歌单 / 音源 │
├─────────────────────────────────────────────┤
│                                             │
│  panel（滚动区，不透明）                      │
│    ├ 搜索：input + 结果列表（64px 行）        │
│    └ 歌单：歌单标签 + 行列表                  │
│                                             │
├─────────────────────────────────────────────┤
│  player bar（64px，玻璃，三列等分）           │   ← 固定
│  [封面46+标题/歌手] [⏮ ⏯ ⏭] [模式 音量 词 全屏]│
└─────────────────────────────────────────────┘
```

- 播放条 64px，封面 46px（条高 − 18），`border-radius: 8px`
- 三列 `grid-template-columns: minmax(0,1fr) auto minmax(0,1fr)`，中间控件绝对稳定
- 进度条 2px 轨道贴播放条顶部边缘，滑块默认透明、hover 才出现
- 主内容 `padding-bottom: 64px + 16px`，播放条不遮挡最后一行

## 五、列表行规格

```
┌──────────────────────────────────────────────────────┐
│ [48] 标题（14/600）                       04:19  [···] │  64px
│      歌手 · 平台（12.5/灰）                           │
└──────────────────────────────────────────────────────┘
```

- 行高 64px，媒体槽固定 48px + 右侧 16px 间距 → 文字始终同一左边缘
- 标题 14px/600 主墨色；副行 12.5px 灰，`歌手 · 平台`
- 时长右对齐 `tabular-nums`，宽度固定 48px
- 行内操作（收藏 / 加歌单 / 更多）默认 `opacity: 0`，`:hover` 或 `:focus-within` 时 `opacity: 1`
- 正在播放：左侧 3px 青色竖条 + 标题变青色 + 封面显示播放中图标（**不用整行填充**）
- hover 背景：`rgba(255,255,255,.05)`，无位移无阴影，150ms
- 行间不画分割线，靠 64px 节奏与 4px 间隙区分

## 六、沉浸页规格

- 容器 `position: fixed; inset: 0`，背景 = 封面图 `blur(100px) brightness(.4) scale(1.2)` + 深色遮罩
- 左右双栏（≥1000px）：左侧唱片 + 信息（40%），右侧歌词（60%）；窄屏上下堆叠
- 封面 `min(54vh, 320px)`，圆角 20px，慢速旋转（仅播放时）
- 歌词字号阶梯：`clamp(18px, 2.2vw, 26px)`，行高 1.4
- 非当前行 `opacity: .32`，当前行 `opacity: 1` + 青色 + `scale(1.02)`
- 首尾各留 `50vh` 占位，`scrollIntoView({block:'center'})` → 首末句都能居中
- 上下 15% `mask-image` 渐隐
- 控件：底部居中，⏮ ⏯ ⏭ + 词 + ✕，胶囊背景

## 七、落地顺序

1. token 层 + 布局骨架（`#mod-music` 作用域，不影响其他模块）
2. 搜索页：input + 联想 + 结果列表
3. 歌单页：标签 + 行列表 + hover 操作
4. 播放器条：64px 三列 + 细进度条
5. 沉浸页：双栏 + 歌词阶梯 + 首尾留白
6. 子 agent 审核 → 修 → 部署

## 八、验收标准

- [x] 强调色（`#14B8A6`）在任一屏的像素占比 ≤5%（实测搜索页 0.97%、歌单页 0.82%）
- [x] 全站圆角只用 8 / 20 / 999 三种（28px 备用；2px 为进度条细线豁免）
- [x] 所有数字 `tabular-nums` 且右对齐，同一行右边缘一致（实测时长全部对齐到同一 x）
- [x] 行内功能按钮默认不可见，hover 出现（并加 `pointer-events:none` 防误触）
- [x] 滚动区域无 `backdrop-filter`
- [x] 歌词首句与末句都能滚到视口正中
- [x] 1280×720 下所有元素在视口内，无溢出
- [x] 375px 宽下不横向滚动（实测 365 < 375）

## 九、实施记录（v343）

### 已落地

| 项 | 实现 |
| --- | --- |
| 产品面孔 | `.mu-mark`（青色圆角方块 + ♪）+ 「我的音乐台」+ 音源状态副标题 |
| 子导航 | 胶囊，`fit-content`，激活态填 `--mod-ac` + `--mod-ac-glow` 阴影 |
| 播放条 | 64px 固定贴底，三列 grid（`minmax(0,1fr) auto minmax(0,1fr)`），封面 46px，2px 贴顶进度条 |
| 列表行 | 64px 行高，48px 媒体槽，标题 14/600 + 副行 12.5 灰，时长 48px 右对齐 |
| 行内操作 | 绝对定位浮行尾，默认 `opacity:0 + pointer-events:none`，hover/focus-within 显现 |
| 正在播放 | 左侧 3px 竖条 + 标题青色（不整行填色） |
| 沉浸页 | 双栏 38%/62%，唱片 `min(240px,30vh,52vw)`，歌词字号 `clamp(16,1.7vw,20)` → 高亮 `clamp(18,2.1vw,25)` |
| 首尾留白 | JS 按容器高度写入 `.mu-lyr-pad`，配合 `scrollIntoView({block:'center'})` |
| 窄屏 | ≤860px 沉浸页上下堆叠；≤720px 播放条三列压缩；≤480px 隐藏随机/循环 |
| 主题 | token 挂 `:root`，亮色下播放条/弹层/迷你条自动换色 |

### 审核发现并修复的关键缺陷

1. **token 作用域错误**：变量定义在 `#mod-music`，但播放条/沉浸页/Toast 挂在 `body` 上取不到值 → 按钮变方块、背景透明。改挂 `:root`。
2. **`.mu-ops:nth-of-type` 永不匹配**：子元素全是 div，第一个是 `.mu-bar` → 右列控件悬在中间。改用显式类名。
3. **窄屏控件掉出播放条**：只声明两列导致第二组 ops 换行到视口外。
4. **`.mu-imm-disc` 被压成竖条**：grid 子项 `width:56%` 无确定参照。父级改回 flex。
5. **移动端媒体查询被覆盖**：写在基础规则之前，同优先级被后面的 `display:flex` 顶掉。
6. **歌词开关后永久空白**：`showLyric=false` 时 DOM 里没内容，切回只改 class 不重写 innerHTML。
7. **播放条盖住所有模块**：挂 body 后不受模块路由控制，遮住 manual/tarot/films 底部并让迷你条失效。加 `syncBarVisibility()`。
8. **弹层被播放条盖住**：弹层在 `#modules-viewport`（z-index:1）层叠上下文内，压不过 body 上 z=340 的播放条。弹层改挂 body。
9. **隐藏按钮可点**：只设 `opacity:0` 时歌单页的 ✕ 会「看不见但能删歌」。补 `pointer-events`。
10. **`input[type=range]` 缺 `max`**：默认 100，超过 100 秒的歌无法拖动定位。
11. **沉浸页被 `scrollIntoView` 顶走**：`overflow:hidden` 仍是滚动容器，切行时底栏上下跳 44px。改 `overflow:clip`。
12. **`--mod-ac-soft` 全站未定义**：manual / vocab / music 三处背景一直透明。在 `nav.css` 用 `color-mix` 定义。

### 已知未做

- 沉浸页背景未取封面主色（当前用 `--mod-ambient` 径向渐变）
- 播放条与沉浸页的封面在酷我搜索结果缺图时显示 ♪ 占位
